# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running

```bash
.venv/bin/python main.py     # or: python main.py, with pygame installed
```

Run from the repo root — asset paths (`images/...`) and `Highscore.txt` are relative to the working directory. `.venv/` holds Python 3.14 + **pygame-ce** (the maintained community fork; same `import pygame` API — never install the stalled `pygame` package alongside it). `requirements.txt` has the one dependency: `pip install -r requirements.txt` into a fresh venv is the full setup. There is no build step, no lint config, and no test suite.

`Highscore.txt` is local player data, gitignored and not tracked. It is created from `default_scores` on first run, so a fresh clone needs no setup.

## Architecture

Pygame game in a single file, `main.py` (~500 lines), with two selectable modes: **Speed Run** (the original game — two local players, player 1 on WASD, player 2 on the arrow keys, first to 100 points wins) and **Adventure** (single player, playing country-themed levels — currently just Level 1, the UK; hazards and level progression are still to come).

**Modes are table-driven.** `MODES` is a list of rules dicts — `name`, `tagline`, `player_count`, `saves_highscore`, `lives` (starting lives per player, `None` for modes without the lives concept), `levels` — and the global `mode` points at the active one. The mode select screen picks it (up/down move the highlight, ENTER confirms and calls `newRound()` so the players list is rebuilt at the new seat count); the instructions screen then draws the mode's `name`, one controls entry per seat, and the high-score table only when `saves_highscore` is true. The end screen only writes `Highscore.txt` when `saves_highscore` is true (solo times aren't comparable with two-player races). The chosen mode survives rounds and `K_r` restarts — nothing resets it. **A rule that varies by mode belongs in the `MODES` table, not in an `if` on the mode name.**

**Levels are content tables.** A level dict carries everything content-ish about a round: `name`, `point_goal`, the `animals` effects table, the `animal_images`/`rare_animal_images` spawn pools and the `legend_layout`. Speed Run's content is `CLASSIC_LEVEL` (name `None`); Adventure's is the `ADVENTURE_LEVELS` list — the world tour, one country per level, `UK_LEVEL` first (France, Spain etc. append there; continent chapters will group such lists later). The global `level` points at the active one, set in `newRound()` as `mode["levels"][0]` — always index 0 until level progression exists. `runGame()`/`runEndScreen()` read `level["point_goal"]` for the win check; the instructions screen's third line is `level["name"]` when set (Adventure's countries), else the mode tagline. **Content that varies by level (animals, values, goals, and per the roadmap, future spawn scripts/hazards) belongs in the level dict; rules that vary by mode stay in `MODES`.** UK_LEVEL's art is placeholders — existing sprites standing in (rabbit=squirrel, tiger=fox, eagle=swan…); a comment on the table says how to swap in real icons.

**Screen state machine.** Five functions — `runStartScreen()` (title only), `runModeSelect()`, `runInstructions()`, `runGame()`, `runEndScreen()` — each own one screen: its loop, its drawing, its `pygame.display.flip()` and its event handling. Each returns the name of the next screen (`"start"`, `"modes"`, `"instructions"`, `"game"`, `"end"` or `"quit"`), and the small dispatch loop at the bottom of the file hops between them until one returns `"quit"`. The pre-game flow is title → mode select → instructions → game; `K_r` on the end screen goes back to the title. A transition is just a `return`; there are no screen flags to keep in sync. `runGame()` writes `current_time`/`last_time` and `runEndScreen()` writes `scores`/`trophy` through `global` declarations.

**Simulation and rendering are separate.** `updateGame(all_intents, dt)` advances the whole sim — player movement, animal movement, recycling, collisions, scoring — with no drawing and no input reads; it is what a headless server (or a test) runs. Input reaches the sim only as **intent dicts** (`{"left"/"right"/"up"/"down": bool}`, one per player, aligned with `players` by index): `runGame()` reads the keyboard and converts it through `keyboardIntents(pressed, controls)`, and anything that produces the same dict (a replay, an AI, a network packet) can drive a player instead. **New sim behaviour goes in `updateGame()`/the classes' update methods; drawing stays in the `run*` screen functions.**

**Game state lives in module-level globals** (`players`, `animals`, `rng`, `level`, `chosen_color`, `scores`, `trophy`, ...), but every starting value is written in exactly one place: `newRound(seed=None)`. It is called once at startup and again from the `K_r` handler in `runEndScreen()`, just before it returns `"start"`. **Any new piece of round state belongs in `newRound()`** — for per-player state that means `Player.__init__` (newRound builds fresh `Player` objects each round, which is what resets them); anything else is set in `newRound()` directly. **All sim randomness goes through `rng`** (a `random.Random` built in `newRound()` from the optional seed — spawns, gift coin flips, background colour), so a seeded round replays exactly; never call the module-level `random` functions from sim code.

**Players live in the `players` list** — instances of the `Player` class: score, position, shield, hitbox, plus the identity that tells them apart (`number`, control keys, colours, HUD placement), passed as constructor arguments in `newRound()`. The sim (`updateGame`, `collect`) never assumes a player count; `newRound()` builds the seat layout from `mode["player_count"]` — solo modes get one seat on the arrow keys starting mid-screen, two-player modes the classic WASD-vs-arrows pair. `update(intents, dt)` syncs `self.rect` (the 32x32 hitbox at the centre of the 64x64 sprite) to the *pre-move* position — the same one-frame lag as `Animal.update` — then moves; `draw(screen)` and `draw_hud(screen)` are read-only rendering, so a headless sim never calls them.

**Frame-rate independence and pacing.** `dt = (time.time() - last_time) * 60`, clamped to 1.9 to absorb the slow first frames; every movement/velocity value is multiplied by `dt`. The loop is paced by **vsync** (`set_mode(..., pygame.SCALED, vsync=1)` — `SCALED` is required for vsync in pygame-ce): `flip()` blocks until the display refresh, so frames land exactly on the refresh cadence. `clock.tick(240)` is only a runaway guard for when vsync is unavailable — **never pace with `tick(60)` or similar**: a sleep-based timer drifts against the real refresh rate and skips a frame about once a second, which shows as the whole field lurching forward (this was a real bug). Movement constants are deliberately asymmetric (left 5.8, right 7.0). `P` pauses `runGame()`: the field still draws but the sim never steps, the timer's start point slides forward so paused time never counts, and `last_time` stays fresh so `dt` cannot jump on resume.

**Animals are instances of the `Animal` class** (a plain class, not `pygame.sprite`). The constructor rolls the type (1-in-8 from the active level's rare pool) and sets `image_name` (the path, used as the type tag), the shared `img` surface, its own `rect`, position, `speed` and `recycle_x`. `newRound()` spawns 27 as `Animal(slot=i)`, staggered off the left edge. They are recycled rather than pooled: once `x > recycle_x` the object is removed and a fresh `Animal()` appended. Collected animals are parked at `y = 1000` instead of being removed. `update(dt)` syncs the hitbox *before* moving, so collisions track the previous frame's drawn position; below `x = -1000` everything moves at 5 so the spawn queue keeps its pacing.

**Scoring is table-driven.** `level["animals"]` maps each image path to `{effect, value, legend}`, where `effect` is one of `points` / `obstacle` / `opponent` / `shield` / `random` / `deadly` (the collector loses a life and shows the explosion sprite for ~50 frames; a shield absorbs the hit, and the effect is inert when the mode's `lives` is `None`); an entry may also carry `speed` and `recycle_x` (defaults 5 and 1100) for fast, far-recycling animals — that is data, not a special case, and both the classic eagle and the UK swan use it. `Player.collect(image_name, opponents)` looks up the table and mutates the players directly — `opponents` is every other player (the `opponent` effect loops over them, so with one player it is a no-op), and the collision loop in `updateGame()` builds it per collision. Shields are consumed in the `obstacle` branch: the shield absorbs the hit, otherwise the (negative) table value is applied. The instructions screen legend is drawn by looping over `level["legend_layout"]` (image path + two positions) and takes its label text from `level["animals"]`, so point values cannot drift out of step with the legend.

**To add an animal to a level:** add an entry to that level's `animals` table, add the path to its `animal_images` or `rare_animal_images` (rare spawns on a 1-in-8 roll in `Animal.__init__`), and add a `legend_layout` row. A startup assertion fails loudly if any level has a spawnable animal with no `animals` entry. Nothing is index-coupled, so reordering the pools is safe — but keep pool *sizes* matched across levels if you care about seeded rounds consuming the rng stream identically. **To add a level:** write a new level dict (copy `UK_LEVEL`) and append it to `ADVENTURE_LEVELS`; the same image path can mean different things in different levels, since every lookup goes through the level's own table.

**High scores are times, lower is better.** `Highscore.txt` is one line of five space-separated floats sorted ascending. `loadScores()` / `saveScores()` own all file access; `loadScores()` falls back to `default_scores` and rewrites the file if it is missing, empty, corrupt, or short, so the game never crashes on bad data. On the end screen, if the round's time beats `scores[4]` (the worst kept score), the slowest entry is dropped and the file is written — guarded by `not trophy` so it saves once per round rather than on every rendered frame.
