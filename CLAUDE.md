# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running

```bash
.venv/bin/python main.py     # or: python main.py, with pygame installed
```

Run from the repo root — asset paths (`images/...`) and `Highscore.txt` are relative to the working directory. `.venv/` holds Python 3.14 + **pygame-ce** (the maintained community fork; same `import pygame` API — never install the stalled `pygame` package alongside it). `requirements.txt` has the one dependency: `pip install -r requirements.txt` into a fresh venv is the full setup. There is no build step, no lint config, and no test suite.

`Highscore.txt` is local player data, gitignored and not tracked. A missing file simply means "no records yet" (the level shows dashes), so a fresh clone needs no setup — it is written the first time a record is actually earned.

## Architecture

Pygame game in `main.py` (~550 lines) plus `sounds.py` (sound-effect synthesis, see below), with two selectable modes: **Speed Run** (the original game — two local players, player 1 on WASD, player 2 on the arrow keys, first to 100 points wins) and **Adventure** (single player, playing country-themed levels — currently just Level 1, the UK; hazards and level progression are still to come).

**Modes are table-driven.** `MODES` is a list of rules dicts — `name`, `tagline`, `player_count`, `lives` (starting lives per player, `None` for modes without the lives concept), `ends_on_goal` (does reaching `level["point_goal"]` end the round immediately, or does the player keep scoring against it — Speed Run's race is `True`, Adventure's chase is `False`), `saves_highscore`, `score_type` (`"time"`, lower is better, or `"points"`, higher is better), `progress_file`, `levels` — and the global `mode` points at the active one (the high-score file is a per-*level* key, not a mode key; see below). The start screen picks it (up/down move the highlight, ENTER or SPACE confirms and calls `newRound()` so the players list is rebuilt at the new seat count); the instructions screen then draws the mode's `name`, while the level-info screen behind it draws one controls entry per seat and the level's records only when `saves_highscore` is true. The chosen mode survives rounds and both end-screen restart keys — nothing resets it. **A rule that varies by mode belongs in the `MODES` table, not in an `if` on the mode name.**

**Levels are content tables.** A level dict carries everything content-ish about a round: `name`, `point_goal`, the `animals` effects table, the `animal_images`/`rare_animal_images` spawn pools and the `legend_layout`. Eight keys are optional and default to off: `two_star_score` (the Adventure end screen's 2-star threshold, see below; defaults to double `point_goal`), `time_limit` (seconds; running out ends the round the same way running out of lives does — *unless* the level also has a `landmark`, see below), `background_color` (a fixed RGB triple; without it `newRound()` picks a random one from `colours`, as before), `score_color`/`timer_color` (RGB triples read at every render site — `Player.draw_hud()`, both branches of `runGame()`'s timer, and the end screen's score — falling back to the player's own colour and black respectively when unset; `UK_LEVEL` colours both Union-Jack blue, `FRANCE_LEVEL` colours the score red and the timer white against its navy background), `flag` (an image path shown next to the level name on the instructions screen and next to the timer in `runGame()`, as a centred pair with the flag vertically centred against whichever of the two is taller — used by `UK_LEVEL`'s Union Jack), and the `landmark`/`landmark_name` pair (an image path and display name — Big Ben, the Eiffel Tower, the Brandenburg Gate). A landmarked level's clock isn't a hard cutoff: once `time_limit` elapses, `updateGame()` spawns a fixed `Landmark` (its image scaled to half native size) snug against the bottom-left corner instead of ending the round outright — and stops replacing recycled animals from that point on, so the field thins out rather than keeps spawning. `Landmark` is a genuine obstacle, not a target: its own `rect` is the building (solid — touching it crashes), and `sky_rect` is the strip of open air directly above the roofline (clearing it is how you finish). Both are checked in `updateGame()`; clearing sets `landmark_cleared` (read by `runGame()` as an immediate round-end, the same way it reads lives/score elsewhere) and crashing sets `landmark_crashed` *and* force-sets that player's `lives` to 0 with the normal death explosion — which means the round then ends through the ordinary "out of lives" check with no extra case needed. `runEndScreen()` reads `landmark_crashed` to override `reached_goal` to `False` unconditionally: hitting the landmark is always FAILED regardless of score, exactly like running out of lives any other way, and its subtitle reads "Crashed into `landmark_name`!" instead of the generic reasons. The HUD timer hands off to a "Fly over `landmark_name`!" prompt once it spawns. A level with `time_limit` but no `landmark` keeps the plain old behaviour (the clock ends it directly), so this is opt-in per level. Speed Run's content is `CLASSIC_LEVEL` (name `None`, no time limit, random background, no flag); Adventure's is the `ADVENTURE_LEVELS` list — the world tour, one country per level: `UK_LEVEL`, `FRANCE_LEVEL`, `ITALY_LEVEL`, `SPAIN_LEVEL`, `GERMANY_LEVEL`; more countries append there, and continent chapters will group such lists. Each country reuses the same cast shape — a 1-point hedgehog, a 2-point small mammal, a 5-point common animal, a rare fast 10-pointer, the jet in the top half and a road/rail hazard in the bottom half, plus the shield — swapping in national animals and vehicles, so a new country is a table edit rather than new code. All of them share the 30s limit and the 100 goal, and each takes its palette from its flag: UK white with Union-Jack blue, France navy like the football kit, Italy green, Spain red with gold score, Germany a gold field with a red score and black timer. The global `level` points at the active one, set in `newRound()` as `mode["levels"][level_index]` (see `level_index` below). `runGame()`/`runEndScreen()` read `level["point_goal"]` for the win check (only when `mode["ends_on_goal"]` is true — Adventure's goal doesn't end the round, it's just the number the player is chasing past) and `level["time_limit"]` for the timeout check; the instructions screen's third line is `level["name"]` when set (Adventure's countries), else the mode tagline. **Content that varies by level (animals, values, goals, time limits, background, flag, landmark, and per the roadmap, future spawn scripts/hazards) belongs in the level dict; rules that vary by mode stay in `MODES`.**

**Campaign position is `level_index`, a global next to `mode`.** It survives rounds the same way `mode` does: unchanged on a replay (`newRound()` with no other change), reset to 0 whenever a mode is freshly chosen on the start screen, set by the level select screen, and advanced by the end screen's next-level key. `newRound()` clamps it to `len(mode["levels"]) - 1` and reads `level = mode["levels"][level_index]`. Speed Run's one-entry `levels` list means `level_index` is always 0 there in practice.

**Campaign progress is a star rating per level, persisted in `mode["progress_file"]`** (`AdventureProgress.txt`, gitignored player data like the highscore files; `None` for Speed Run, which has no campaign). `loadProgress(mode)`/`saveProgress(mode, stars)` read/write one 0–3 int per level, space-separated, padded with zeros so newly appended levels arrive uncompleted and degrading to all-zeros on missing/corrupt files. Stars are computed once in `runEndScreen()`: **1 star = reach `point_goal`, 2 = reach the level's `two_star_score`, 3 = reach it without losing a life** (`players[0].lives == mode["lives"]`). `two_star_score` is an optional level key (UK and France both set it to 150) defaulting to double `point_goal` when a level doesn't set one. Only a *better* rating is saved — a worse replay never downgrades. One star is also the unlock bar: level *i* is playable once level *i−1* has ≥1 star. The end screen draws the earned stars bright and the missing ones ghosted (alpha) under the score, so the player sees what was left on the table.

**The end screen has two independent layouts, chosen by `mode["player_count"]`.** Two-player (Speed Run) keeps the original design: a per-player WINS!/OUT OF LIVES!/TIME'S UP! line, the elapsed time (the whole point of a race), fixed-position highscores top right. Solo (Adventure) is a redesigned, fully centred column, built with a running `cursor` y-offset incremented by each surface's *real* `get_height()` rather than a guessed constant — impact's glyphs render far taller than their point size suggests, so a hardcoded constant silently overlapped the rows below it the first time this was tried. The solo layout: a SUCCESS!/FAILED banner (gold/red) based on `reached_goal = any(p.score >= level["point_goal"] for p in players)` — the same "did you cross the goal" test that ends Speed Run's race also works as Adventure's win/lose split, since Adventure's round can end via lives or the clock without ever crossing it; a failure-only reason line ("Out of lives!"/"Time's up!"); the score itself, big and centred, in `score_font`; a next-level line that is **always shown but changes meaning** — `"Next: <name>"` (gold, actionable) when the goal was reached and a next level exists, `"Reach N points to unlock <name>"` (dim, informational) when it wasn't, or `"More countries coming soon!"` when there's no next level at all (the only case reachable today, since Adventure has just the one level); the trophy row (icon + caption side by side, not stacked — there's no vertical room to spare) when `trophy` is set; both records on one compact line rather than a stacked pair; and a controls line that only mentions `N: Next Level` when it would actually do something. **The N key only advances `level_index` when `reached_goal and has_next`** — failing a level never unlocks the next one, only replaying it (R) does. No time display on the solo screen: Adventure levels cap at 30s, so it added little.

**Screen state machine.** Six functions — `runStartScreen()` (title and mode select combined: up/down move the highlight, ENTER or SPACE confirms), `runLevelSelect()` (campaign modes only — one row per level with flag and earned stars, locked rows dimmed and refusing to confirm with the hurt buzz; rows run from y=250 to a last row at y=520 at the classic 90px spacing while that fits and tighten as countries are added, since a fixed 90 walked the fifth level off the bottom of the 600px window), `runInstructions()`, `runLevelInfo()`, `runGame()`, `runEndScreen()` — each own one screen: its loop, its drawing, its `pygame.display.flip()` and its event handling. Each returns the name of the next screen (`"start"`, `"levels"`, `"instructions"`, `"info"`, `"game"`, `"end"` or `"quit"`), and the small dispatch loop at the bottom of the file hops between them until one returns `"quit"`. The pre-game flow is start → levels (only when `len(mode["levels"]) > 1`, so Speed Run skips straight on) → instructions → game; ESC from instructions steps back one screen (levels for campaign modes, start otherwise).

**The instructions screen is a menu; the reference material lives on its own page.** `runInstructions()` deliberately carries only the round's *identity* — mode heading, level name and flag, the UFO and the landmark prompt — plus a two-item highlighted menu (`Start Level` / `Level Info`) driven the same way as the mode- and level-select screens (up/down or W/S move the highlight, ENTER or SPACE confirms). `runLevelInfo()` holds everything reference-ish that used to be crammed alongside it: the controls line (one entry per seat, so it still matches the mode), the `legend_layout` animal table and the level's high scores. The controls sit in the band between the heading and the legend's first middle-column row — the one gap free in every level's `legend_layout`, since the side columns start at y=30 but never reach that far in from the edges. ENTER starts the level from the info page too, so a player who came to check the numbers doesn't have to backtrack; ESC returns to the menu. Both `runInstructions()` layouts (solo and two-player) stack their content from a running `cursor` incremented by each surface's real `get_height()` and then place the menu below it — the same technique, and for the same reason, as the solo end screen: a hardcoded y silently overlaps the row beneath it the moment a level's content runs taller than guessed (the Sagrada Familia's name is the case that used to collide with the old on-screen highscore column). **New per-level reference content belongs on the info page, not the instructions menu** — keeping that screen short is the entire point of the split. On the end screen, `K_r` calls `newRound()` and goes straight back to instructions for the same level, `K_n` (success with a next level only) advances `level_index` first, and `K_m` goes back to start. A transition is just a `return`; there are no screen flags to keep in sync. `runGame()` writes `current_time`/`last_time` and `runEndScreen()` writes `scores`/`trophy` through `global` declarations.

**Simulation and rendering are separate.** `updateGame(all_intents, dt)` advances the whole sim — player movement, animal movement, recycling, collisions, scoring — with no drawing and no input reads; it is what a headless server (or a test) runs. Input reaches the sim only as **intent dicts** (`{"left"/"right"/"up"/"down": bool}`, one per player, aligned with `players` by index): `runGame()` reads the keyboard and converts it through `keyboardIntents(pressed, controls)`, and anything that produces the same dict (a replay, an AI, a network packet) can drive a player instead. **New sim behaviour goes in `updateGame()`/the classes' update methods; drawing stays in the `run*` screen functions.**

**Sound is presentation, fed by a sim event queue.** `sounds.py` synthesises every effect at startup from square/sine waves and filtered noise — stdlib only, no audio files, nothing to download; swapping one for a recorded file is one line in `sounds.init()` (`pygame.mixer.Sound("file.wav")`). Latency depends on `pygame.mixer.pre_init(44100, -16, 2, 512)` being called **before** `pygame.init()`; `sounds.init()` runs after, and with no audio device everything is a safe no-op (the game runs silent). The sim never touches the mixer: `Player.collect` appends event names (`collect`/`collect_big`/`hurt`/`zap`/`shield_up`/`shield_break`/`explosion`) to the module-level `sound_events` list, and `runGame()` drains it after each `updateGame()` step and calls `sounds.play(name)` — the mirror image of the intents flow, so a headless server can forward or ignore the same list. `newRound()` clears the queue. UI sounds (`menu_move`/`menu_select`, the end-screen `jingle_win`/`jingle_lose`/`trophy`) are played directly by the screen functions since they are not sim events; the end screen plays exactly one jingle, chosen after the trophy check so a record run gets the fanfare. **New sim-driven sounds go through `sound_events`, never a direct `sounds.play()` call from sim code.** The synthesised UFO engine hum loops on reserved mixer channel 0 (one-shot effects cannot steal it) and belongs to `runGame()`: `start_hum()` on entry, `stop_hum()` before *every* `return`, and per-frame volume via `set_hum_level("paused"/"idle"/"moving")` — silent when paused, swelling under thrust. Keep its fundamental at 110Hz or higher; a 55Hz version was inaudible on laptop speakers. Background music was tried and removed (2026-08-21, the user didn't like it) — the tune, the ducking scheme and the per-screen `sounds.tick()` calls are in git history if it ever comes back.

**Game state lives in module-level globals** (`players`, `animals`, `rng`, `level`, `chosen_color`, `scores`, `trophy`, ...), but every starting value is written in exactly one place: `newRound(seed=None)`. It is called once at startup and again from the `K_r` handler in `runEndScreen()`, just before it returns `"instructions"`. **Any new piece of round state belongs in `newRound()`** — for per-player state that means `Player.__init__` (newRound builds fresh `Player` objects each round, which is what resets them); anything else is set in `newRound()` directly. **All sim randomness goes through `rng`** (a `random.Random` built in `newRound()` from the optional seed — spawns, gift coin flips, background colour), so a seeded round replays exactly; never call the module-level `random` functions from sim code.

**Players live in the `players` list** — instances of the `Player` class: score, position, shield, hitbox, plus the identity that tells them apart (`number`, control keys, colours, HUD placement), passed as constructor arguments in `newRound()`. The sim (`updateGame`, `collect`) never assumes a player count; `newRound()` builds the seat layout from `mode["player_count"]` — solo modes get one seat on the arrow keys starting mid-screen, two-player modes the classic WASD-vs-arrows pair. `update(intents, dt)` syncs `self.rect` (the 32x32 hitbox at the centre of the 64x64 sprite) to the *pre-move* position — the same one-frame lag as `Animal.update` — then moves; `draw(screen)` and `draw_hud(screen)` are read-only rendering, so a headless sim never calls them.

**Frame-rate independence and pacing.** `dt = (time.time() - last_time) * 60`, clamped to 1.9 to absorb the slow first frames; every movement/velocity value is multiplied by `dt`. The loop is paced by **vsync** (`set_mode(..., pygame.SCALED, vsync=1)` — `SCALED` is required for vsync in pygame-ce): `flip()` blocks until the display refresh, so frames land exactly on the refresh cadence. `clock.tick(240)` is only a runaway guard for when vsync is unavailable — **never pace with `tick(60)` or similar**: a sleep-based timer drifts against the real refresh rate and skips a frame about once a second, which shows as the whole field lurching forward (this was a real bug). Movement constants are deliberately asymmetric (left 5.8, right 7.0). `P` pauses `runGame()`: the field still draws but the sim never steps, the timer's start point slides forward so paused time never counts, and `last_time` stays fresh so `dt` cannot jump on resume.

**Animals are instances of the `Animal` class** (a plain class, not `pygame.sprite`). The constructor rolls the type (1-in-8 from the active level's rare pool) and sets `image_name` (the path, used as the type tag), the shared `img` surface, its own `rect`, position, `speed` and `recycle_x`. `newRound()` spawns 27 as `Animal(slot=i)`, staggered off the left edge. They are recycled rather than pooled: once `x > recycle_x` the object is removed and a fresh `Animal()` appended. Collected animals are parked at `y = 1000` instead of being removed. `update(dt)` syncs the hitbox *before* moving, so collisions track the previous frame's drawn position; below `x = -1000` everything moves at 5 so the spawn queue keeps its pacing.

**Scoring is table-driven.** `level["animals"]` maps each image path to `{effect, value, legend}`, where `effect` is one of `points` / `obstacle` / `opponent` / `shield` / `random` / `deadly` (the collector loses a life and shows the explosion sprite for ~50 frames; a shield absorbs the hit, and the effect is inert when the mode's `lives` is `None`); an entry may also carry `speed` and `recycle_x` (defaults 5 and 1100) for fast, far-recycling animals — that is data, not a special case, and both the classic eagle and the UK swan use it — and `y_range` (defaults `(120, 500)`, the field's full vertical band) to confine an animal to part of it, which the UK jet (top half) and bus (bottom half) use. `Player.collect(image_name, opponents)` looks up the table and mutates the players directly — `opponents` is every other player (the `opponent` effect loops over them, so with one player it is a no-op), and the collision loop in `updateGame()` builds it per collision. Shields are consumed in the `obstacle` branch: the shield absorbs the hit, otherwise the (negative) table value is applied. The level-info screen's legend is drawn by looping over `level["legend_layout"]` (image path + two positions) and takes its label text from `level["animals"]`, so point values cannot drift out of step with the legend.

**To add an animal to a level:** add an entry to that level's `animals` table, add the path to its `animal_images` or `rare_animal_images` (rare spawns on a 1-in-8 roll in `Animal.__init__`), and add a `legend_layout` row. A startup assertion fails loudly if any level has a spawnable animal with no `animals` entry. Nothing is index-coupled, so reordering the pools is safe — but keep pool *sizes* matched across levels if you care about seeded rounds consuming the rng stream identically. **To add a level:** write a new level dict (copy `UK_LEVEL`) and append it to `ADVENTURE_LEVELS`; the same image path can mean different things in different levels, since every lookup goes through the level's own table.

**High scores are level-owned: two records per level, not a top-five table.** Each level carries its own `highscore_file` — Speed Run's one-level `CLASSIC_LEVEL` tracks times in `Highscore.txt`, lower is better; each Adventure country tracks points in its own file (`UKHighscore.txt`, `FranceHighscore.txt`, ...), higher is better, so a result set in one country never shows up in another's. A level keeps exactly **two** records, indexed by the `RECORD_BEST`/`RECORD_CLEAN` constants: the best result ever, and the best result set **without losing a single life**. The clean record is the harder target and is what keeps a level worth replaying once the raw best is out of reach. Modes whose `lives` is `None` (Speed Run's race) only have the first — a no-lives-lost run is not a meaningful thing there — and `recordRows()` is what encodes that, returning one row for such modes and two otherwise. The file is one line of two space-separated tokens, each a float or `UNSET` (`"-"`) for "not earned yet", so an unplayed level shows a dash rather than an invented seed score (this is why levels no longer carry a `default_scores` key). `loadRecords(path)` / `saveRecords(path, records)` take the *active level's* `highscore_file` (read in `newRound()`, written in `runEndScreen()`; none are in git — `.gitignore` matches the family with `*Highscore.txt`). `loadRecords()` degrades to `[None, None]` on a missing, empty or corrupt file, and **collapses a legacy five-score file to a single best** (min for time, max for points) rather than reading its first two entries as nonsense. `mode["score_type"]` still decides the metric, and `beatsRecord(value, record)` is the single place that knows a lower time but a higher score is the improvement; an unset record is beaten by anything. `formatRecord()` renders ints for points, raw floats for time, and the dash for unset. **`runEndScreen()` settles both records once, before its draw loop** — alongside `reached_goal` and `stars`, since the round is over and none of it changes per frame (the old version recomputed inside the loop and needed a `not trophy` write-guard). `new_best` and `new_clean` are tracked separately so a run can take the clean record without being the best overall; `trophy` is either of them, and the caption reads "New High Score!" only when `new_best` is set, "New No-Death Record!" otherwise, so a run never claims a high score it didn't set.
